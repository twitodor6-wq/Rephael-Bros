# Rafael Brothers — M4.7.7-S1 | Rafi Run Sprite Integration POC

## משימת Work: שילוב ספרייט ריצה ראשון במשחק הקיים

**תקשורת:** בעברית. **סביבת יעד:** משחק Phaser 3 דו־ממדי לדפדפן, HTML עצמאי, תשתית מודולרית ו־Stage/Asset JSON.  
**נקודת הפתיחה המחייבת:** חבילת המקור המלאה והמאומתת של **M4.7.6** (יש לצרף בנפרד).  
**חבילת הנכסים:** `Rafi_Run_Prototype_Asset_Pack_v0.2_WITH_WORK_PROMPT.zip` (מצורפת בנפרד; מכילה ספרייט ניסויי).  
**יעד המיילסטון:** POC ממוקד של אנימציית ריצה לרפי, **לא** החלפת מערכת הדמויות ולא הפקת רקעים.

## 0. כללי בטיחות ו-Baseline
1. פתח וקרא את `README_START_HERE`, `HANDOFF`, `QA_REPORT`, `KNOWN_ISSUES`, מסמכי הארכיטקטורה, Schema ו-Asset Loader של M4.7.6, ככל שקיימים.
2. ודא שגרסת הבסיס היא M4.7.6 והרץ בדיקות ובניית baseline **לפני** שינויים. שמור נקודת שחזור ומדוד hash של קובצי מקור חשובים.
3. אל תתחיל משחק מחדש, אל תמחק יכולות, ואל תשנה את פיזיקת Arcade, מודלי סרט המדידה Manual/Classic/Hybrid, עוגנים, פטיש, מקדחה, קפיצות, התנגשות, חידות או שלבים. אל תיגע במערכות Camera/Parallax שתוקנו.
4. לפי דוח המסירה, M4.7.6 הוכיחה שש ריצות Spawn→Exit ב-Chromium Canvas; **WebGL מלא, Safari ומשחק אנושי אינם מוכחים**. אל תציג אותם כהצלחות ללא הרצה בפועל.
5. התייחס לנכסי `PROTOTYPE` כאל ניסוי בלבד: ערוץ השקיפות חולץ heuristically מווידאו H.264 דחוס, וקיימים סיכוני fringe, דחיסה וקפיצות pivot. אין להכריז עליו Production Ready.

## 3. מימוש POC שמרני
1. רשום את הספרייט במניפסט נכסים JSON נפרד, עם גרסה, frame size, rows/cols, fps, loop ומעמד `prototype`, בלי לשנות מקור נתוני פיזיקה.
2. טען את ספרייט הריצה פעם אחת דרך loader/adapter. דאג לטעינה ואריזה תקינות גם כ-HTML מקומי/offline (לפי מנגנון הבנייה הקיים).
3. בזמן **ריצה על הקרקע של רפי בלבד**, הצג את ה-RUN החדש **כייצוג חזותי**, הצמוד לגוף השחקן הקיים. אל תיצור גוף פיזיקלי חדש או קוליידר נוסף לספרייט.
4. בעת עצירה, קפיצה, נפילה, שימוש בכלים, חיבור לסרט או מעבר לשאול — העדף תצוגת דמות קיימת/מאושרת או fallback מפורש. שמור את כל יכולות המשחק.
5. התאם renderScale ו-origin/pivot בשימוש בנתונים ממניפסט ובצילום בדפדפן. התייחס לבעיה האפשרית של 'ריקוד' הדמות בפריימים, ויישר ויזואלית את כפות הרגליים ללא שינוי world position או hitbox. הימנע ממתיחת אנימציה ומהחלפת צורת הדמות.
6. Flip X בעת שינוי כיוון בלי טעינה כפולה; בדוק ריצה לשני הצדדים.
7. הוסף **toggle ברור** להפעלה/ביטול של `Rafi Run Prototype` (QA/Visual Modules או הגדרות Asset, בהתאם לארכיטקטורה), עם fallback לגרפיקה הישנה. כיבויו צריך לשחזר חזותית את ה-baseline; המכניקה חייבת להישאר זהה בשני המצבים.
8. דאג לניקוי אובייקטי רינדור/אנימציות בעת restart, החלפת דמות, החלפת שלב ו-destroy, בלי כפילויות או דליפות.
9. **אל תכניס רקעים חדשים במיילסטון זה.** זהו ניסוי Sprite בלבד, לפני Background Asset Pipeline.

## 4. QA ודרישות ראיות
- הרץ validation ו-test/build הקיימים, בלי להחליף בדיקות מהגרסה הקודמת.
- בדוק ב-Chromium Canvas את רפי: שמאלה/ימינה, התחלה/עצירה, קפיצה/נחיתה, פטיש, מקדחה, סרט מדידה, toggle on/off, restart, death/respawn והחלפה לשאול. וודא שהגרפיקה לא נתקעת וששאול אינו מקבל את ספרייט רפי.
- בצע השוואת לוגים/טלמטריה של מיקום גוף, מהירויות, rope events ו-collision on/off; הבדלים מותרים רק ברינדור, לא בפיזיקה.
- בדוק נתיבי Asset Loader ובניית HTML עצמאי; צלם פריימים ו/או הקלטת QA של ריצה, עמידה ושינוי כיוון. דווח על קצוות שקיפות, קפיצות גוף, ghost sprite, foot sliding, שינוי קנה מידה.
- הרץ בדיקת smoke נפרדת ל-WebGL **אם הסביבה תומכת**; כישלון או אי-יכולת מסומנים `NOT PROVEN`. Safari ו-Human Play גם `NOT PROVEN` ללא בדיקה אמיתית.
- בדוק Regression לפי יכולת: רפי/שאול, שלושת מצבי rope, אמצעי ניווט וכלים. אל תצהיר על שש ריצות מלאות בגרסה החדשה בלי להריץ אותן בפועל.
- פעל בלולאת Development → Independent-style QA review → Fix → Retest; תעד כשלים אמיתיים, לא רק pass.
